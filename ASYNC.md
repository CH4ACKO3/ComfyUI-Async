# Async GPU groups

This fork runs up to two workflows concurrently by default. Each workflow keeps the upstream dependency, lazy-input and dynamic-subgraph scheduler, and dispatches ready nodes to isolated worker processes. Use `--async-workers N` to change the workflow limit, or `--async-workers 0` to use the upstream executor.

Right-click a native Group and open **Execution GPUs**. All GPUs are enabled by default; click checkboxes to toggle them without closing the menu. The group header displays the allowed GPUs without changing its saved title. At least one GPU must remain enabled to submit its nodes. Selecting several GPUs creates a scheduling pool, not tensor parallelism. Settings are saved in the group's `flags.gpu_devices` and exported to each node's `_meta.gpu_devices` in API prompts. A node belongs to the smallest group containing its center (including the boundary); equal-sized groups use the lowest group ID, independent of drawing order. GPU lists are not combined across overlapping groups. Nodes outside all groups retain native device selection and follow the device of input model objects.

Put model loaders and their consumers in the same GPU group. Models and arbitrary custom objects stay in their owning process; separate loaders are needed for separate GPUs. Tensors can cross groups through CPU memory. Native loop controllers remain in the graph coordinator. Custom nodes using process-global state, custom HTTP routes, or live graph mutation may need adaptation; `--async-workers 0` provides the compatibility path. This version targets local GPUs; CUDA is verified, while ROCm and other backends are unverified. Remote workers are not implemented.

Different GPUs can execute simultaneously. A shared per-GPU admission lock serializes nodes on the same GPU across workflows. Workers offload managed models after each call so idle processes do not hold another workflow's VRAM; weights remain cached in system RAM. Output nodes also share a lock to prevent filename collisions. Failed nodes are not replayed unless their class declares `ASYNC_RETRY_SAFE = True`; non-output nodes with that declaration get up to three attempts on OOM, with bounded backoff. A model that cannot fit still fails normally.

Intermediate outputs use a per-workflow-worker LRU cache (128 entries by default, configurable with `--cache-lru`; `--cache-none` disables it). This replaces the upstream RAM-pressure cache because coordinator processes cannot measure remote object storage. Changing a GPU assignment invalidates affected cached results. Interrupting a workflow stops its worker processes and clears its caches without interrupting other workflows. Cold worker startup and CPU transfers add latency; this implementation prioritizes isolation over single-GPU throughput.
