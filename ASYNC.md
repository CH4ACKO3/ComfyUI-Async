# Async GPU groups

This fork runs up to two workflows concurrently by default. Each workflow keeps the upstream dependency, lazy-input and dynamic-subgraph scheduler, and dispatches ready nodes to isolated worker processes. Use `--async-workers N` to change the workflow limit, or `--async-workers 0` to use the upstream executor.

Right-click a native Group and open **Execution GPUs**. All GPUs are enabled by default; click checkboxes to toggle them without closing the menu. The group header displays the allowed GPUs without changing its saved title. Turning all GPUs off restores native device selection, just like nodes outside groups; it does not force CPU execution or inherit GPU lists from overlapping groups. Selecting several GPUs creates a scheduling pool, not tensor parallelism. Settings are saved in the group's `flags.gpu_devices` and exported to each node's `_meta.gpu_devices` in API prompts. A node belongs to the smallest group containing its center (including the boundary); equal-sized groups use the lowest group ID, independent of drawing order. GPU lists are not combined across overlapping groups. Nodes outside all groups retain native device selection and follow the device of input model objects.

Put model loaders and their consumers in the same GPU group. Models and arbitrary custom objects stay in their owning process; separate loaders are needed for separate GPUs. Tensors can cross groups through CPU memory. Native loop controllers remain in the graph coordinator. Custom nodes using process-global state, custom HTTP routes, or live graph mutation may need adaptation; `--async-workers 0` provides the compatibility path. This version targets local GPUs; CUDA is verified, while ROCm and other backends are unverified. Remote workers are not implemented.

Each GPU has one persistent worker, with up to two concurrent node calls by default (`--async-node-concurrency N`; use `1` for serial execution). Calls have separate node instances, CUDA streams, progress and cancellation state, including multiple list inputs to the same node. Native checkpoint, UNet, CLIP and VAE loaders share cached base weights through native model clones (up to eight loader configurations per GPU); custom loaders do not participate in this cache.

Concurrent sampling currently supports plain UNet-based SD/SDXL `KSampler` and `KSamplerAdvanced` with Euler, ordinary conditioning and no model patches, hooks or additional models. A native full-load delegate keeps one shared set of resident GPU weights; each invocation gets its own sampler/model wrapper and an activation-memory reservation. Loading, unloading and incompatible calls wait for active readers. Low/no-VRAM mode, models that cannot fit the reservation, and unsupported sampling configurations retain native serial execution. The Comfy compiler is disabled in concurrent device workers because its shared state is not reentrant; concurrency `1` retains the native compiler setting.

Basic image operations can overlap, and custom nodes can declare `ASYNC_CONCURRENT_SAFE = True` when isolated instances can run without mutating shared inputs, process globals or managed-model residency. Unmarked custom nodes remain exclusive. Output nodes share a lock to prevent filename collisions. Eligible plain samplers and non-output nodes declaring `ASYNC_RETRY_SAFE = True` receive up to three attempts on OOM, with backoff and serial retries after active calls drain. Other failed nodes are not replayed. A model that cannot fit still fails normally.

Intermediate outputs use a per-coordinator LRU cache (128 entries by default, configurable with `--cache-lru`; `--cache-none` disables it). This replaces the upstream RAM-pressure cache because coordinators cannot measure remote object storage. Changing a GPU assignment invalidates affected cached results. Interrupting a workflow signals only that request and releases its cached outputs while retaining shared workers and weights. Custom nodes must cooperate with native interruption; a blocking custom call can delay cancellation. The native free-memory action clears workers and caches once active workflows finish. `GET /async/status` reports worker PIDs, pending calls, peak concurrency and model-cache counters. Worker progress/preview events include `call_id` and `list_index`; `async_node_start`/`async_node_end` identify individual invocations.

## Continuous inputs

Native Run and auto-queue modes continue to work. API clients can also include this field in `POST /prompt` alongside the usual prompt and client ID:

```json
{"extra_data": {"execution_session": {"id": "canvas-1", "revision": 1, "policy": "latest"}}}
```

Use a stable client/session ID and an increasing revision for each input snapshot. `latest` keeps the running input and replaces pending inputs with the newest one; `fifo` admits every input in queue order, allows multiple inputs from the same session in flight, and returns HTTP 429 at 64 pending inputs per session. FIFO results may finish out of order; use their revisions to associate outputs. `latest` keeps coordinator affinity to reuse unchanged graph results. The overall workflow concurrency limit remains `--async-workers`. Revision tracking retains the 256 most recent sessions, evicting only idle sessions; switching sessions on a coordinator clears its graph cache but retains device model weights.

Progress, execution and metadata-bearing preview events include `execution_session`. Replaced inputs receive an `execution_superseded` event and a matching unsuccessful history entry. Clients should display only results matching their desired revision. Image inputs must use distinct filenames per revision so later uploads cannot overwrite queued snapshots. This API does not yet add a painting node or replace the frontend's existing auto-queue triggers.
