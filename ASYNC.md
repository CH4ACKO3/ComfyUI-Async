# Async GPU groups

This fork propagates tagged node-change events through resident graphs, with no fixed event-concurrency limit. The native dependency, lazy-input and dynamic-subgraph machinery dispatches ready node versions to shared device queues. The whole-workflow submission endpoint and serial-executor switch have been removed.

Right-click a native Group and open **Execution GPUs**. All GPUs are enabled by default; click checkboxes to toggle them without closing the menu. The group header displays the allowed GPUs without changing its saved title. Turning all GPUs off restores native device selection, just like nodes outside groups; it does not force CPU execution or inherit GPU lists from overlapping groups. Selecting several GPUs creates a scheduling pool, not tensor parallelism. Settings are saved in the group's `flags.gpu_devices` and exported to each node's `_meta.gpu_devices` in API prompts. A node belongs to the smallest group containing its center (including the boundary); equal-sized groups use the lowest group ID, independent of drawing order. GPU lists are not combined across overlapping groups. Nodes outside all groups retain native device selection and follow the device of input model objects.

Put model loaders and their consumers in the same GPU group. Models and arbitrary custom objects stay in their owning process; separate loaders are needed for separate GPUs. Tensors can cross groups through CPU memory. Native loop controllers remain in the graph coordinator. Node interfaces are unchanged. Custom nodes relying on cross-process globals, custom HTTP routes, or unsupported live graph mutation remain subject to process-isolation limits. This version targets local GPUs; CUDA is verified, while ROCm and other backends are unverified. Remote workers are not implemented.

Each GPU has one persistent worker. Node concurrency follows available memory by default, with no fixed call-count limit; `--async-node-concurrency N` optionally caps it (`1` runs serially). Samplers use native activation-memory estimates, and other parallel calls reserve at least 512 MiB. Waiting inputs do not each occupy a compute thread in the device worker. Calls have separate node instances, CUDA streams, progress and cancellation state, including multiple list inputs to the same node. Native checkpoint, UNet, CLIP and VAE loaders share cached base weights through native model clones (up to eight loader configurations per GPU); custom loaders do not participate in this cache.

Concurrent sampling currently supports plain UNet-based SD/SDXL `KSampler` and `KSamplerAdvanced` with Euler, ordinary conditioning and no model patches, hooks or additional models. A native full-load delegate keeps one shared set of resident GPU weights; each invocation gets its own sampler/model wrapper and an activation-memory reservation. Loading, unloading and incompatible calls wait for active readers. Low/no-VRAM mode, models that cannot fit the reservation, and unsupported sampling configurations retain native serial execution. The Comfy compiler is disabled in concurrent device workers because its shared state is not reentrant; concurrency `1` retains the native compiler setting.

Basic image operations can overlap, and custom nodes can declare `ASYNC_CONCURRENT_SAFE = True` when isolated instances can run without mutating shared inputs, process globals or managed-model residency. Unmarked custom nodes remain exclusive. Output nodes share a lock to prevent filename collisions. Eligible plain samplers and non-output nodes declaring `ASYNC_RETRY_SAFE = True` receive up to three attempts on OOM, with backoff and serial retries after active calls drain. Other failed nodes are not replayed. A model that cannot fit still fails normally.

Current node versions and versions needed by active events stay resident. A per-graph LRU retains up to 128 additional historical outputs (`--cache-lru`; `--cache-none` retains only live versions). In-flight calls with the same node/version are shared. Each event has its own dependency view; a join waits for changed upstream versions and reuses the unchanged versions selected when that event was accepted. Registered nodes use explicit refresh versions instead of polling `IS_CHANGED`; internal dynamic nodes retain native fingerprints. Interrupting one event detaches its consumers and cancels a shared call only when nobody still needs it. A blocking custom call can delay reclamation. The native free-memory action clears workers and caches once active inputs finish. `GET /async/status` reports worker PIDs, pending calls, peak concurrency and model-cache counters. Worker progress/preview events include `call_id` and `list_index`; `async_node_start`/`async_node_end` identify individual invocations.

## Node events

Run refreshes source nodes (nodes without incoming links); Run Selected refreshes the selected nodes. Edits do not submit events by default. Set a node’s native **Mode → On Event** to submit its input changes automatically, grouped within 150 ms. The mode is saved with the workflow; loading a workflow, enabling On Event and layout-only edits do not execute nodes. Pending edits to other nodes are included in the next manual or automatic submission. Native seed-widget callbacks still apply. Both Run and edits use the same event API; neither posts a full workflow for execution.

Register a graph without running it using `PUT /graphs/{graph_id}` with `{"client_id": "canvas", "nodes": {...}}`. Graph IDs and event IDs are UUIDs. Submit an atomic change with `POST /graphs/{graph_id}/events`:

```json
{
  "client_id": "canvas",
  "event_id": "b6d639b7-8d82-498c-bacd-72174cef085a",
  "base_revision": 0,
  "changes": {"8": {"class_type": "PrimitiveInt", "inputs": {"value": 123}}},
  "refresh": []
}
```

`changes` replaces the listed node definitions; `null` removes a node. `refresh` forces listed nodes to produce a new version even when their inputs are unchanged. All changes in a request share one revision. Required inputs must belong to that revision's dependency view, so late results from another event cannot be mixed into a join. Unchanged upstream values are reused even while their producer is still running. Affected nodes are validated before the change is committed; stale `base_revision` requests receive HTTP 409. `GET /graphs/{graph_id}?client_id=canvas` returns the accepted definition and revision.

The response and progress/output events identify the graph, revision and event ID (`graph_event`); `prompt_id` is the event ID used by the existing history, progress and cancellation UI. Events can finish out of order. Image inputs must use distinct filenames for distinct contents. Drawing-specific gesture integration is not included; serialized node-input changes already use this event path. `POST /prompt` and `execution_session` have been removed. Existing `add_on_prompt_handler` callbacks preprocess a private graph snapshot once per event. Their input and link changes participate in that event’s revision and downstream scheduling; submitted definitions remain separate so preprocessing can remove links without losing them for later events. Hooks that rely on mutable process globals or server-to-worker shared state still need adaptation.
